# Jetpack Compose / UI のルール

## 状態の持ち方

- **UI 状態は ViewModel が持ち、Composable は受け取って描くだけにする**（状態ホイスティング）。
  画面の Composable は「状態」と「イベントのラムダ」を引数に取る形を基本にする
- ViewModel は `viewModel()` / `hiltViewModel()` で取得する。
  **自分で `remember { MyViewModel() }` しない**（構成変更で作り直され、状態が消える）
- **画面をまたいで共有する状態は、共有したい範囲のスコープで ViewModel を取る**
  （ナビゲーショングラフ単位など）。画面ごとに取ると、戻ったときに**別インスタンスになる**
- `remember` は「再コンポーズをまたいで保持したいもの」、`rememberSaveable` は
  「プロセス再生成をまたいで保持したいもの」。**用途が違うので置き換えない**

## 再コンポーズを壊さない

- `LazyColumn` / `LazyRow` の `items` には**安定した `key`** を渡す
  （渡さないと並べ替え・削除で状態が別の行に付く）
- 副作用は `LaunchedEffect` / `DisposableEffect` の中で起こす。
  **Composable の本体で I/O や状態更新をしない**（毎回の再コンポーズで走る）
- `LaunchedEffect` の `key` に「毎回変わる値」（新しく作ったラムダやリスト）を渡さない。
  **無限に再実行される**

## 文字サイズ・レイアウト

- **文字サイズは `MaterialTheme.typography.*` を使う。** 直接 `sp` を書かない
  （端末の文字サイズ設定に追従しなくなる）
- **要素の高さを `height()` で固定しない。`heightIn(min = ...)` を使う**
  （文字を大きくした利用者の画面で**文字が切れる**）
- タッチターゲットは **48dp 以上**を確保する（`minimumInteractiveComponentSize` / `sizeIn`）
- 入力欄を含む画面は `Modifier.imePadding()` と `verticalScroll()` を併用する
  （キーボードで隠れて操作できなくなる）
- 色は `MaterialTheme.colorScheme` から取る。**画面ごとに色を直書きしない**
  （ダークテーマ・動的カラーで破綻する）

## ナビゲーション

- ルート（画面の識別子）と引数は**1箇所に集約**して定義する。文字列を各画面に直書きしない
- 「戻る」は `navigateUp()` を使う。`popBackStack()` を素で呼ぶとバックスタックが壊れやすい
- 同じ画面を積み上げたくない遷移は `launchSingleTop` / `popUpTo` を明示する
- **遷移経路を増やしたら `docs/設計書/画面遷移一覧.md` を更新する**

## 読み込み中・空・エラー

画面は最低でも次の状態を持つ。**「読み込み中」と「空」を同じ表示にしない**:

| 状態 | 表示 |
|------|------|
| 読み込み中 | プレースホルダ（キャッシュがあるなら**キャッシュを出す**） |
| 空 | 「まだありません」と、次に何をすればよいか |
| エラー | 何が起きたかと、**再試行の手段** |

## アクセシビリティ

- アイコンだけのボタンには `contentDescription` を必ず付ける（装飾なら明示的に `null`）
- 色だけで情報を伝えない（形・ラベルを併用する）
- コントラスト比を確保する。薄いグレーの上の白文字を作らない

## プレビューと実機確認

- 主要な画面には `@Preview` を用意する。**ただしプレビューは実機確認の代わりにはならない**
- UI を変更したら `/harness-android:capture-screenshots` で実機・エミュレータの画面を撮り、
  **自分で画像を確認してから**完了報告する
