# データ層（永続化・同期）のルール

## クライアントは必ずシングルトンにする

**DataStore・Room・HTTP クライアントは、アプリ内で1インスタンスに保つ。**

- `DataStore` は**同じファイルを2回開くと実行時エラーになる**
  （`There are multiple DataStores active for the same file`）。
  `Context.dataStore` の拡張プロパティで定義するか、DI コンテナで1つに束ねる
- Room の `Database` インスタンスは `Room.databaseBuilder` を毎回呼ばない
  （接続とキャッシュが分裂し、片方の更新がもう片方に見えない）
- **画面やリポジトリのコンストラクタで `new` しない。** 生成場所を1箇所に決める

## Room

- DAO の戻り値は、**購読したいものは `Flow`、1回きりの取得は `suspend fun`**
- **スキーマを変えたらマイグレーションを書く。** `fallbackToDestructiveMigration()` は
  **利用者のデータを消す**ので、開発中のみ・意図的に選ぶ場合に限る
- 主キー・一意制約・インデックスを最初に決める。後から足すとマイグレーションが増える
- エンティティは `data` 層の型。**そのまま UI へ渡さない**（`domain` のモデルへ変換する）

## DataStore / 設定値

- キー定義は1箇所に集約する。**画面ごとにキー文字列を直書きしない**
- 既定値は読み出し側で `?: default` するのではなく、**キーごとに1箇所で決める**
- 認証情報・トークンは平文で保存しない（暗号化された保存先を使う）

## キャッシュファースト（推奨する既定）

外部データ（ネットワーク・ContentProvider・他アプリ）を扱う画面は、
**ローカルを正として即座に表示し、裏で同期する**:

```
ローカル（Room）を Flow で購読 → 即座に表示
      ↓ 同時に
バックグラウンドで取得 → ローカルへ書き込み → Flow 経由で自動反映
```

- 画面は**同期の完了を待たない**。待つと毎回「読み込み中」から始まる
- 同期の失敗は**画面を空にしない**。既存の表示を残したままエラーを伝える
- 書き込みは**楽観的更新**（先にローカルを更新して即座に反映し、失敗したら戻す）を検討する。
  戻す処理を書けないなら楽観的更新にしない

## バックグラウンド処理

- 継続が必要な処理（同期・アップロード）は `WorkManager` を使う。
  **一意な名前**（`enqueueUniqueWork`）で登録し、多重起動を防ぐ
- ネットワーク・充電などの制約は `Constraints` で宣言する。自前で条件分岐しない
- **アプリが終了しても続く処理を、コルーチンのスコープに載せない**

## 権限を要求するデータ源

連絡先・通話履歴・SMS・位置など、権限が要る API を叩く層では:

- **呼び出し前に権限を確認する。** 拒否されている場合の戻り値を決めておく（例外で落とさない）
- 権限は**使う直前に要求する**。起動時にまとめて要求しない
- **拒否されたときの画面**（説明と設定への導線）を必ず用意する
- 宣言している権限と要求タイミングを `docs/設計書/権限一覧.md` に反映する
