# 新規設計書の作成

機能開発・改修・バグ修正のいずれかに対応する設計書を作成する。

判定基準・フローの詳細は同梱の [開発フローと規模判定.md](開発フローと規模判定.md) を参照（必要になった時点で読む）。

## Step 1: 変更の性質と規模をユーザーに確認

テンプレートを読み込む前に、以下を確認する:

1. **変更の性質**（AI が推測して提示、ユーザー承認）: 新規追加 / 改修 / バグ修正
2. **変更規模**（AI が推測して提示、ユーザー承認）:
   - S: 1〜2ファイル、データ構造変更なし、UX変更なし
   - M: 3〜10ファイル、既存パターンに沿った変更、UX変更なし
   - L: 10ファイル超、新パターン、データ構造変更あり、または **UX変更あり**

判定ルール:
- 判定に迷ったら **L 寄りで提示する**
- UX 変更を含む場合は自動的に **L 扱い**

**提示例**:
```
指示内容から以下と判断します:
- 変更の性質: 新規追加
- 変更規模: M 規模（既存パターンに沿った項目追加、関連ファイル5つ程度、UX変更なし）

この判定で進めてよいですか？
```

## Step 2: 曖昧さの解消（`[NEEDS CLARIFICATION]`）

**L 規模では必須。M 規模でも仕様が曖昧な場合は実施する。**

設計書に推測を書き込む前に、確定していない事項を洗い出してユーザーに質問する。

### やること

1. 依頼内容から、以下の観点で未確定事項を列挙する:
   - 対象範囲（どこまでを含むか / 含まないか）
   - 入力の許容範囲（未入力・上限・異常値の扱い）
   - 失敗時の挙動（エラー表示・リトライ・ロールバック）
   - 既存機能との関係（置き換えるのか、併存するのか）
   - 完了条件（どうなったら「できた」と言えるか）
2. 各項目を **選択肢つきの質問**にしてユーザーに提示する（自由記述だけの質問にしない）
3. 回答を設計書の「3-3. 未解決事項」表に記録する
4. その場で決められない項目は `❓ 未解決` のまま残し、本文の該当箇所に
   `[NEEDS CLARIFICATION: 何が不明か]` を書く

### 禁止事項

- **未確定事項を推測で埋めて設計書を書き進めない**
- 「後で決める」で放置しない（未解決として明示的に残す）

**Stage 1 のレビュー・承認前に、未解決事項は 0 件にすること。**

## Step 3: テンプレートをコピーして設計書を作成

1. テンプレートを読み込む:
   - プロジェクトに `docs/features/TEMPLATE.md` があればそれを使う（プロジェクト固有の調整が入っている可能性があるため優先）
   - 無ければ本スキル同梱の [TEMPLATE.md](TEMPLATE.md) を使う
2. 以下の命名規則でファイルを作成:
   - パス: `docs/features/yyyymmdd_$ARGUMENTS.md`
   - 日付は本日の日付（yyyymmdd 形式）
3. メタ情報を埋める:
   - 全体ステータス: `🔵 設計中`
   - 変更の性質 / 変更規模: Step 1 で確定した値
   - **Stage 1 ステータス**: L 規模 = `🔵 記入中` / M 規模（UX変更なし）= `⚪ 不要` / S 規模 = `⚪ 不要`
   - **Stage 2 ステータス**: M/L 規模 = `⚪ 未着手` / S 規模 = `⚪ 不要`
   - 未解決事項: Step 2 で残った件数
   - 作成日・最終更新: 本日の日付
4. タスク一覧を記入する。**L 規模では依存関係と並列可否 `[P]` を必ず埋める**（S/M では該当列を削除してよい）

## Step 4: ユーザーへの報告

- 作成したファイルパス
- 変更の性質と規模（確定値）
- 未解決事項の件数（残っている場合は内容も）
- **次のアクション**:
  - **L 規模**: Stage 1（機能・画面設計＋受け入れ基準チェックリスト）を記入 → `/harness-core:design-review feature`
  - **M 規模（UX変更なし）**: Stage 2（技術設計）を記入 → `/harness-core:design-review tech`
  - **バグ修正（M/L）**: 「1. 概要 > 背景」に症状、「1. 概要 > 方針」に根本原因を記入
- 💡 UI・挙動の変更を含む場合は「5. 動作確認計画」も記入する旨を案内する
  （確認手段は `.claude/harness.config.json` の `verification` を参照）
